# 真实素材试用记录模板

> 这是空白记录格式，不是试用证据。只有实际运行、核对预期规格并记录结果后，才能把状态改为“已完成”。合成样例和人为制造的错误要单独标记，不能写成真实使用反馈。

## 试用前

- 选择一个真实的课程、社媒或 UI 素材交付场景。
- 从任务说明、设计规范或交付方要求中取得尺寸和大小上限；不要把图片当前尺寸直接当作正确规格。
- 准备完整的预期清单，至少核实一项正常素材；若项目声称没有漏项，还需能确认全部应交文件。
- 保持原始素材不变；使用 JSON 清单和素材目录运行点检。报告中的绝对路径或私有文件名在公开前要先删改。
- 记录运行时的提交和工具版本，方便别人复跑。

## 运行命令

在仓库根目录把下列示例路径替换为本次试用的清单和素材目录：

```sh
moon version --all
git rev-parse HEAD
moon run --target native cmd/main -- ./trial/media-pack.json ./trial/assets --output ./trial/report
```

通过时 CLI 返回码应为 `0`；发现与清单不符的素材时仍会保存 HTML/JSON 报告并返回非零状态。保留实际终端输出和报告，再逐条与原始规格核对。

## 结论边界

若没有找到真实问题，写“本次样本未发现问题”，不要写成工具已证明项目没有问题。若没有完整、可信的预期清单，只能报告观察到的情况，不要声称已测出漏报率。人为改错的清单可用于验证诊断流程，但须标为受控测试，不能替代真实试用。
